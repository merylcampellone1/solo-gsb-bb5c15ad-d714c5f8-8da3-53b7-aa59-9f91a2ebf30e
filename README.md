# ABX 盲听测试

一个纯本地的音频 ABX 双盲对比 Web 应用。上传 A、B 两段同格式音频后，服务端生成随机 X 题序（提交前映射完全隐藏），你在 A / B / X 之间自由切换试听并逐题作答（答案 + 把握度），提交后一次性揭晓正确率、逐题映射与把握度校准报告（分档实际正确率 + 95% Clopper–Pearson 精确置信区间）。

- 后端：Node.js + Express
- 前端：浏览器 Web Audio API（无框架、无构建步骤）
- 数据：音频与会话状态（含隐藏 X 映射、盐）**仅保存在本机** data 目录，不经过任何外部服务；未提交会话可跨进程重启恢复

## 功能特性

- 上传 A、B 两个**同格式**音频（WAV / MP3 / FLAC / OGG / M4A / AAC / OPUS / WebM / AIFF）
- **题数规划器（上传页独立工具）**：输入预期正确率 p（0.51～0.99）、显著性水平 α（0.01 / 0.05 / 0.10）与目标功效（0.80 / 0.90 / 0.95），对 n = 1～50 逐个取满足 `P[Bin(n,0.5) ≥ k] ≤ α` 的最小整数门槛 k（无可行门槛的题数跳过），并用**精确二项尾概率**（非正态近似）计算实际功效 `P[Bin(n,p) ≥ k]` 与假阳性概率；返回功效达标的最小 n、其 k、实际功效与假阳性概率，并展示全部 n 的门槛 / 功效表，1～50 题内无可行题数时明确提示；可一键把推荐 n 填入题数字段，由你自行开始测试。规划器为纯只读统计计算，**不创建会话、不上传或保存任何数据**
- 统一时间轴：自动以较短音频的时长为准
- 服务端用加密随机数生成每题 X = A 或 B 的映射，提交前任何接口都不泄露
- X 音频以 chunked 流式下发（无 Content-Length / 文件名），避免按文件大小猜测
- 试听页在 A / B / X 间切换时**保持播放位置与暂停状态**，可拖动进度条
- **片段循环（A–B 循环）**：在统一时间轴上一键设置入点 / 出点（区间至少 0.5 秒，不足时自动调整），播放到出点即采样级精确跳回入点；切换 A / B / X、换题或拖动进度后循环区间与播放 / 暂停状态保持，且循环点不会越过较短音频的有效时长；进度条下方高亮显示循环范围与启用状态，可一键清除
- **可选电平匹配**：解码后在统一时间轴内汇总各声道样本计算 RMS，以较安静音源为基准仅衰减较响者（-24～0 dB），A / B / X 经 GainNode 按同一规则生效；界面显示 A/B 调整量（dB），开关关闭立即恢复原始电平，消除响度差造成的盲测线索
- **可配置的等功率交叉淡化**：A / B / X 切换时新旧音源从同一时间位置并行播放，按 sin/cos 等功率曲线完成增益交接，时长 5～100 ms 可调（默认 30 ms），可整体关闭；快速连续切换时从当前听感增益重新锚定并取消过时节点与回调，不叠加、不爆音、不漂移；循环区间与电平匹配在淡化期间同时生效
- 逐题作答，可随时返回任意题目修改答案；全部作答后才能提交
- **逐题把握度**：每题除答案外还需选择把握度（50%～100%，每 10% 一档），与答案一起保存、修改、恢复；两项齐全才允许提交
- **把握度校准报告**：提交后按把握度分档展示题数、答对数、实际正确率与 95% Clopper–Pearson 精确置信区间（服务端对二项尾概率数值反解，概率绝对误差 ≤ 1e-6，不用正态近似）；结果页在同一 0～100% 横轴上绘制把握度标记、实际正确率点与置信区间，未落入区间的把握度标记突出显示，直观判断主观信心是否可靠；空档显示「无数据」
- **可恢复会话（服务重启后仍有效）**：创建测试后生成本机恢复标识，刷新、重新打开页面甚至**重启服务 / 重建容器**后，都可凭原恢复标识找回未提交的会话（当前题号、已选答案与把握度、题目音频、隐藏题序与题序承诺值均与重启前一致）。会话状态在创建时与每次作答成功响应前原子写入 data 目录；启动时只恢复未过期、A/B 音频完整且记录合法的会话，损坏 / 缺文件 / 半写入的记录一律不恢复
- **题序承诺核验（commit–reveal）**：创建会话时服务端生成 32 字节随机盐，按 `abx-v1|会话ID|题数|逐题A/B串|盐` 计算 SHA-256 承诺值；提交前创建 / 状态 / 恢复接口只返回承诺值，不泄露盐与映射；浏览器把承诺值随恢复信息保存在本机，恢复时若与服务端返回值不一致则阻止继续答题；提交后结果才揭示盐与映射，结果页用 Web Crypto 重算并与最初保存的承诺值比对，明确显示「核验通过 / 核验失败 / 无法核验」
- 提交后一次性揭示：总正确率 + 逐题「X 实际是 / 你的答案 / 把握度 / 对错」+ 把握度校准报告
- 提交或删除后恢复标识立即失效；会话默认 24 小时过期自动清理，也可手动删除

## 快速开始

### 方式一：Docker（推荐，单条命令）

```bash
docker compose up --build
```

启动后访问：**http://localhost:3000**（端口 `3000`）

更换宿主机端口：

```bash
PORT=8080 docker compose up --build
```

停止并清理数据卷：`docker compose down -v`

> **会话恢复与容器**：恢复标识明文保存在浏览器 localStorage 中，会话状态（含 X 映射、盐的哈希级秘密）与音频一起保存在命名卷 `abx-data` 里。`docker compose restart` 或重新 `up`（不删卷）后，服务启动时会扫描卷内 `data/<会话ID>/state.json`，未提交会话可凭原恢复标识继续，已保存答案、把握度、隐藏题序与承诺值保持不变；已提交 / 已删除 / 已过期 / 损坏或缺音频的记录不会被恢复。`docker compose down -v` 会连同卷一起删除，所有会话不可恢复。

### 方式二：本地 Node.js（单条命令）

```bash
npm install && npm start
```

启动后访问：**http://localhost:3000**（端口 `3000`，可用 `PORT` 环境变量覆盖）

要求 Node.js ≥ 18。

## 使用流程

1. 打开首页，可先用下方的**题数规划器**估算合适的题数（见下）；选择音频 A 和音频 B（需同格式），设置题目数量（1–50，默认 8；也可由规划器一键填入推荐值）
2. 点击「开始测试」，浏览器解码音频并进入试听页
3. 每题中点击 **A / B / X** 切换音源对比试听，切换时播放位置与暂停状态保持不变；可开启「切换淡化」并设置时长（5–100 ms，默认 30 ms）让新旧音源等功率平滑交接，不需要时可在界面关闭；可开启「电平匹配」消除 A/B 响度差造成的盲测线索；可用「⇤ 设为入点 / 设为出点 ⇥」循环试听某一片段（见下）
4. 对每题选择「X = A」或「X = B」，并选择把握度（50%～100%，每 10% 一档；50% 表示纯靠猜，100% 表示确定无疑）；答案与把握度都随题即时保存，可通过「上一题 / 下一题」或进度圆点返回修改（进度圆点实心 = 两项齐全，空心描边 = 只填了一项）
5. 全部题目两项齐全后点击「提交并揭晓答案」，一次性查看正确率、逐题映射与把握度校准报告；结果页同时进行**题序承诺核验**：浏览器用 Web Crypto 按创建时的格式把揭示出的盐与题序重算承诺值，与创建会话时本机保存的原值比对，显示「核验通过 / 核验失败 / 无法核验」

**题序承诺核验的含义**：这是一种 commit–reveal（先承诺、后揭示）机制。创建会话时服务端就确定了逐题 X 映射，并给出其加盐 SHA-256 承诺值；答题期间映射与盐完全隐藏，提交后才揭示。浏览器重算的承诺值与最初保存的一致（**核验通过**），即证明从创建到提交这段时间里题序映射没有被中途改动（例如服务端根据你的作答临时调换 X）；不一致（**核验失败**）则说明揭示数据与当初的承诺不符，结果不可信。若本机没有创建时保存的原承诺值（例如清理过浏览器数据），显示**无法核验**——此时不会拿服务端当前返回的承诺值代替原值做比对，因为那无法发现中途篡改。

**把握度校准（Calibration）**：提交后按自评把握度分档统计。对每档 n 题中答对 k 题，视答对数 Y 服从二项分布 Bin(n, p)，计算 95% Clopper–Pearson **精确**置信区间：下界为方程 P(Y ≥ k | p) = 0.025 的解，上界为方程 P(Y ≤ k | p) = 0.025 的解（k = 0 时下界为 0，k = n 时上界为 1）。区间由服务端对二项尾概率做二分法数值反解得到，概率绝对误差不超过 1e-6，不使用正态近似。结果页中所有元素共用同一条 0～100% 横轴：◆ 为自评把握度，● 为该档实际正确率，横条为置信区间；把握度标记未落入区间时标红突出——落在区间右侧说明**过度自信**，左侧说明**信心不足**；没有题目的档位显示「无数据」。

**题数规划器**：上传卡片下方的独立工具，用于在测试前估算题数，整个过程不创建会话、不写任何存储。输入三项参数——预期正确率 **p**（你估计自己真实听辨的正确率，0.51～0.99；0.5 为纯靠猜故下限取 0.51）、显著性水平 **α**（允许的假阳性率，0.01 / 0.05 / 0.10）、**目标功效**（真实正确率确为 p 时能检出的概率，0.80 / 0.90 / 0.95）。对每个题数 n（1～50），判定规则是「答对至少 k 题则认为并非纯靠猜」：k 取满足假阳性概率 `P[Bin(n, 0.5) ≥ k] ≤ α` 的最小整数门槛（1～n）；若连答对全部 n 题都无法把假阳性压到 α 以内（如 α = 0.01 时 n ≤ 6），该 n 没有可行门槛，表中标记并跳过。对有门槛的 n，再用真实正确率 p 计算实际功效 `P[Bin(n, p) ≥ k]`。规划器返回功效达到目标的**最小 n** 及其 k、实际功效、假阳性概率，并列出 n = 1～50 的完整门槛 / 功效表（达标行打勾、推荐行高亮）；若 50 题内没有任何题数达标（例如 p = 0.51、α = 0.05、目标功效 0.80 时，50 题内功效最高也只有约 6%），明确提示无可行题数，并建议提高 p、放宽 α 或降低目标功效。点击「将推荐题数填入上方题数字段」只会回填题数输入框并高亮提示，是否开始测试仍由你选择音频并点击「开始测试」决定。所有概率均为精确二项尾概率（log 系数展开、逐项求和），**不使用正态近似**；越界或非数值输入（含空值）一律返回错误提示。

**片段循环（A–B 循环）**：播放或暂停时点击「⇤ 设为入点」「设为出点 ⇥」，即可把当前播放位置设为循环起点 / 终点（先后次序不限）。出点设定后播放立即从入点继续，形成无缝循环；循环区间最短 **0.5 秒**，若设定的区间不足会自动调整入 / 出点满足下限。进度条下方的高亮条实时显示循环范围与入 / 出点刻度，状态行显示「循环已启用 / 未设置」；「清除循环」一键取消。切换 A / B / X、切换题目或拖动进度都不会清除循环区间，也不会改变播放 / 暂停状态（拖动到出点之后时，本次会播放到时间轴末尾，回到区间内后循环继续生效）；循环点始终限制在较短音频的有效时长内。

**中断与恢复**：测试进行中刷新或重新打开页面，首页会出现「继续上次测试」卡片，点击即可回到上次题号继续作答（已选答案、把握度与题目音频一并找回）；**服务重启（含 `docker compose restart`、容器重建但保留卷）后同样有效**——创建会话与每次作答成功响应前，状态都会以「临时文件 + fsync + 原子改名」写入会话目录的 `state.json`，重启后恢复出的答案、把握度、隐藏题序与承诺值与重启前完全一致。恢复时浏览器会把服务端返回的题序承诺值与创建时本机保存的原值对照，若发现变化则阻止继续答题并提示「题序承诺核验异常」，只能放弃并删除该会话；也可以主动选「放弃并删除该会话」。启动恢复只接受未过期（默认 24h）、A/B 音频完整且 `state.json` 逐字段合法、承诺值可用记录内盐与映射重算自洽的会话；损坏的 JSON、缺音频、篡改过的映射、半写入的 `state.json.tmp` 或过期记录一律不恢复并清除目录。提交、删除或会话过期后，恢复标识立即并**持续**失效（落盘状态同步作废，重启也不会复活），卡片不再出现。

## 实现原理

- **统一时间轴**：前端用 `decodeAudioData` 解码 A、B 后取 `min(durationA, durationB)` 作为播放上限，所有音源共用该时间轴
- **进度保持**：播放引擎记录「起始偏移 + AudioContext 起始时刻」，切换音源时在原偏移处重建 `AudioBufferSourceNode` 继续播放；暂停状态下切换只换缓冲
- **片段循环**：入 / 出点基于统一时间轴（秒），启用时使用 `AudioBufferSourceNode` 原生 `loop` + `loopStart` / `loopEnd`，到达出点采样级精确跳回入点；显示位置按「入点 + (经过时长 − 入点) mod 区间」回绕。设置 / 清除循环点时以当前位置无缝重建播放（保持播放 / 暂停状态），设定出点时若当前位置已越过出点则立即跳回入点；循环点被钳制在统一时间轴（较短音频时长）内，区间不足 0.5 秒时自动调整
- **电平匹配**：可选。解码后在统一时间轴内汇总全部声道样本计算 RMS，以较安静音源为基准仅衰减较响音源（限制在 -24～0 dB；RMS < 1e-6 或非有限值时保持 0 dB）。A、B 与每题 X 各经一个 `GainNode` 按同一规则应用增益，切换音源 / 拖动进度 / 换题不中断播放，关闭开关立即恢复原始电平
- **等功率交叉淡化**：可选，时长 5～100 ms。每个发声实例为 `AudioBufferSourceNode → 淡化 GainNode → 电平匹配 GainNode`；切换音源时全部旧实例按 cos 曲线从各自当前听感增益（读取音频渲染线程的实时值）淡出并定时回收，新实例从同一时间位置按 sin 曲线淡入，交接中总功率保持恒定；快速连续点击会取消过时的增益事件与回收定时器并重新锚定，始终平滑转向最后一次选择；暂停、拖动、换题、循环变更立即收束全部实例与回调，保持原有状态语义
- **映射隐藏**：X 映射只保存在服务端本机（运行时内存 + 会话目录内不对外提供的 `state.json`，静态服务仅暴露 `public/`）；`/trial/:n/x` 接口以 `application/octet-stream` + chunked 传输下发音频，不暴露文件大小与文件名
- **题序承诺核验**：创建会话时服务端生成 32 字节随机盐，对 `abx-v1|会话ID|题数|逐题A/B串|盐的十六进制` 计算 SHA-256 作为承诺值；提交前创建、状态、恢复接口只返回承诺值（不返回盐与映射），浏览器在创建时把承诺值随恢复信息存入本机 localStorage。恢复时浏览器比对服务端返回的承诺值与本机原值，不一致则阻止继续答题并提示异常。提交后结果才揭示盐与映射（重复提交与已提交状态读取返回同一揭示数据），结果页用 Web Crypto 按同一格式重算承诺值并与最初保存的原值比对：一致显示「核验通过」，不一致显示「核验失败」；本机没有原承诺值时显示「无法核验」，不以服务端当前值代替
- **把握度校准**：把握度与答案一并存入服务端会话（保存 / 修改 / 恢复走同一接口）；提交时按 6 个档位（50%～100%）分组，对每组 (n, k) 用二分法反解二项尾概率方程得到 Clopper–Pearson 精确区间（单点概率按 log 系数展开计算避免溢出，n ≤ 50 直接求和；k = 0 时下界取 0，k = n 时上界取 1），概率绝对误差 ≤ 1e-6，不使用正态近似；提交前任何接口都不返回正确率、置信区间或 X 映射
- **题数规划器**：`/api/plan` 为无状态只读接口，复用同一套精确二项尾概率函数（`binomPmf` log 系数展开 + `binomUpperTail` 逐项求和，n ≤ 50，不使用正态近似）。对每个 n 从 k = 1 起线性搜索满足 `P[Bin(n,0.5) ≥ k] ≤ α` 的最小整数 k（1～n），找不到则该行标 `feasible: false`；找到后计算 `P[Bin(n,p) ≥ k]` 作为实际功效，取第一个（即最小 n）功效 ≥ 目标值者作为推荐。p / α / 目标功效在服务端做严格有限数与白名单校验，越界或非数值输入一律 400，不做静默回退；接口不触碰会话表、文件系统与任何存储，规划本身不创建会话
- **可恢复会话（跨重启持久化）**：创建会话时服务端生成高熵随机恢复标识（recovery token），明文仅随创建响应下发一次，由浏览器保存在本机 localStorage；服务端只存其 SHA-256 哈希。恢复接口 `/api/session/recover` 凭标识只返回非敏感状态（题数、已选答案与把握度），绝不提前返回 X 映射；当前题号由浏览器本地记录。**会话状态（逐题答案 / 把握度 / 隐藏映射 / 盐 / 承诺值 / 创建时间 / 恢复标识哈希 / 提交标记）原子持久化在会话目录的 `state.json` 中：创建会话与每次作答、提交在成功响应前先写同目录 `state.json.tmp`、fsync 后原子 rename 替换；写入失败返回 5xx 且不改变已确认状态**。服务启动时扫描 `data/`：恢复未过期、A/B 音频为非空文件且记录逐字段合法（含用记录内盐与映射重算承诺值自洽）的未提交会话并重建恢复标识索引，已提交会话只重建为只读结果（重复提交与状态读取仍返回同一揭示数据）、不恢复恢复标识；过期、损坏、缺文件、半写入的目录一律清除。提交（`tokenHash` 置空落盘）、删除（同步删除目录，失败时落盘作废）或过期清理时标识立即并持续失效，重启也不会复活
- **本地存储**：音频与 `state.json` 会话状态写入本机 `./data/<sessionId>/`（Docker 中为命名卷 `abx-data`），重启后按上述规则恢复；会话默认 24 小时过期，运行时定时清理与启动恢复时都会清除过期目录

## API 一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/plan?p=&alpha=&targetPower=` | 题数规划器（只读，**不创建会话**）：p ∈ 0.51～0.99，alpha ∈ 0.01/0.05/0.10，targetPower ∈ 0.80/0.90/0.95；返回 n = 1～50 各行的最小门槛 k、假阳性概率 `P[Bin(n,0.5)≥k]`、实际功效 `P[Bin(n,p)≥k]`（精确二项尾概率，非正态近似），以及功效达标的最小题数 `recommendation`（无则为 `null`，并附范围内功效最高的 `best`）；越界或非数值参数返回 400 |
| POST | `/api/session` | 上传 A/B（multipart 字段 `a`、`b`、`numTrials`），创建会话与随机题序，状态原子写入 data 目录后返回恢复标识 `recoveryToken` 与题序承诺值 `commitment`（不含盐与映射）；落盘失败返回 500 且不创建会话 |
| POST | `/api/session/recover` | 凭 `{token}` 找回未提交会话的非敏感状态（题数、已选答案与把握度、题序承诺值；不含盐与 X 映射）。**服务重启后接口不变，凭原 token 即可继续**；已提交 / 已删除 / 已过期 / 损坏或缺音频的会话返回 404 |
| GET | `/api/session/:id` | 会话状态（题数、已答答案与把握度、题序承诺值；不含盐与 X 映射，提交前不含任何结果；已提交时返回与提交接口相同的揭示数据；重启后同样可用） |
| GET | `/api/session/:id/audio/A`（或 `B`） | 下载参考音频（重启后音频从 data 目录重新读取） |
| GET | `/api/session/:id/trial/:n/x` | 下载第 n 题的 X（按隐藏映射返回 A 或 B 的内容；重启后映射从 `state.json` 恢复） |
| POST | `/api/session/:id/answer` | 保存/修改某题答案与把握度 `{trial, answer, confidence}`（answer ∈ `A`/`B`，confidence ∈ `50`/`60`/…/`100`，可分开更新）；**成功响应前状态原子落盘，落盘失败返回 500 且已确认状态不变** |
| POST | `/api/session/:id/submit` | 全部题目答案与把握度齐全后提交，一次性返回正确率、逐题映射、把握度校准（分档题数/答对数/实际正确率/95% Clopper–Pearson 精确区间）与题序承诺揭示数据（盐 `salt`、题序映射 `mapping`、承诺值 `commitment`）（幂等，重复提交（**含重启后**）返回同一揭示数据）；恢复标识同时持久化作废 |
| DELETE | `/api/session/:id` | 删除会话及其音频文件（同步删除后才响应，重启也不会复活）；恢复标识同时持久化失效 |

## 重启恢复：调用示例

会话状态在**创建时与每次作答成功响应前**原子写入 data 目录，因此未提交测试可跨服务重启继续；HTTP API 在重启前后完全一致，浏览器侧无需任何改动（刷新页面即出现「继续上次测试」）。以下 `curl` 示例演示全过程：

```bash
# ---------- 重启前 ----------
# 1) 创建会话（上传 A/B 与题数），记下 recoveryToken
curl -s -X POST http://localhost:3000/api/session \
  -F a=@a.wav -F b=@b.wav -F numTrials=8
# {"id":"113dfd9c-…","numTrials":8,
#  "recoveryToken":"CWrxGu1yIOoEIKcq---7H77LQZ1ns_BeaXGKq-iBlYM",
#  "commitment":"62ced8fe…"}

ID=113dfd9c-b82c-4b0d-a3f5-a647e900e916
TOKEN=CWrxGu1yIOoEIKcq---7H77LQZ1ns_BeaXGKq-iBlYM

# 2) 逐题作答（每次成功响应前 state.json 已原子落盘；失败返回 500，旧答案不变）
curl -s -X POST http://localhost:3000/api/session/$ID/answer \
  -H 'Content-Type: application/json' \
  -d '{"trial":0,"answer":"A","confidence":80}'
# {"ok":true}

# 3) 随时读取非敏感状态（提交前不返回盐与 X 映射）
curl -s http://localhost:3000/api/session/$ID
# {"id":"…","numTrials":8,"answers":["A",null,…],"confidences":[80,null,…],
#  "commitment":"62ced8fe…","submitted":false}

# 此时重启：Ctrl-C 后重新 npm start；Docker 下为 docker compose restart
# data/<id>/ 下的 A.wav、B.wav、state.json 保证已落盘

# ---------- 重启后 ----------
# 4) 凭【原恢复标识】继续（接口、请求、响应与重启前完全相同）
curl -s -X POST http://localhost:3000/api/session/recover \
  -H 'Content-Type: application/json' -d "{\"token\":\"$TOKEN\"}"
# {"id":"…","numTrials":8,"answers":["A",null,…],"confidences":[80,null,…],
#  "commitment":"62ced8fe…","submitted":false}   ← 答案/把握度/承诺值与重启前一致

# 5) 音频与 X 流照常下发（映射已从 state.json 恢复）
curl -sO http://localhost:3000/api/session/$ID/audio/A
curl -sO http://localhost:3000/api/session/$ID/trial/0/x

# 6) 继续作答、提交——结果与不重启时完全一致
curl -s -X POST http://localhost:3000/api/session/$ID/submit
# {"results":{ …,"salt":"…","mapping":"AAB…","commitment":"62ced8fe…"}}

# 7) 失效语义（重启前后一致，且重启不复活）
curl -s -o /dev/null -w '%{http_code}\n' -X POST \
  http://localhost:3000/api/session/recover \
  -H 'Content-Type: application/json' -d "{\"token\":\"$TOKEN\"}"
# 404  —— 提交/删除/过期后恢复标识持续失效
curl -s -X POST http://localhost:3000/api/session/$ID/submit
# {"results":{ … }}  —— 已提交后重复提交（即使又重启过）仍返回同一揭示结果
```

启动时目录 `data/<id>/state.json` 的处理规则：

| 启动时磁盘状态 | 处理 |
| --- | --- |
| 记录合法、未过期、A/B 音频为非空文件、承诺值重算自洽（未提交） | 恢复，原 token 可继续 |
| 记录合法且已提交 | 恢复为只读结果（GET / 重复提交幂等），token 不恢复 |
| 已超过 `SESSION_TTL_MS` | 不恢复，删除目录 |
| JSON 损坏 / 字段非法 / 承诺值不自洽 / 缺 A 或 B 音频 | 不恢复，删除目录 |
| 仅有半写入 `state.json.tmp`（崩溃于原子改名之前） | 忽略并清除；同目录合法 `state.json` 照常恢复 |

Docker 下 `docker compose restart`、`docker compose up -d`（镜像重建但保留命名卷）等价于上述重启；`docker compose down -v` 删除卷后不可恢复。

## 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 服务监听端口 |
| `DATA_DIR` | `./data`（容器内 `/app/data`） | 音频与 `state.json` 会话状态保存目录（挂载持久卷即可跨重启恢复） |

## 说明与限制

- 音频格式支持取决于浏览器的解码能力（`decodeAudioData`）
- 未提交会话的状态保存在本机 data 目录（会话目录内原子写入的 `state.json`，含隐藏映射与盐，不离开本机），服务重启 / 容器重启（保留 `abx-data` 卷）后凭原恢复标识继续；已提交 / 已删除 / 已过期 / 损坏 / 缺音频的记录不会被恢复（恢复标识持续失效）；清空 data 目录或 `docker compose down -v` 后无法恢复
- 恢复标识明文只保存在本机浏览器 localStorage，服务端仅存其 SHA-256 哈希；换浏览器 / 换设备无法恢复；清理浏览器站点数据会使标识丢失且无法找回（此时结果页题序承诺核验会显示「无法核验」，但服务端会话在 TTL 内仍保留于 data 目录）
- 题序承诺核验在浏览器侧依赖 Web Crypto（`crypto.subtle`），需在安全上下文中使用（`localhost` 或 HTTPS）；非安全上下文下结果页会显示「无法核验」
- 本工具面向本机自测场景；刻意抓包比对字节流理论上可推断 X，正常使用界面则完全盲测
